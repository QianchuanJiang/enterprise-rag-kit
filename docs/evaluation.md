# 评测标准与数据方案

> 本文说明两件事：(1) 本项目的评测以什么标准衡量可信度；(2) 语料来源如何设计才能保证可复现、合规。
> 核心结论：可信评测取决于「真实跑出的指标 + 可复现的脚本 + 清晰的已知限制」；语料采用「公开数据 + 合成数据」组合，所有指标均在所提交的数据上真实运行得到。
> **项目性质**：本项目为演示与研究性质的参考实现，全部语料均经过脱敏或合成，**不含有任何真实企业的保密或生产数据，不能直接用于工业生产环境**（详见第六节）。

---

## 一、评测可信度基线

本项目对评测的要求统一为以下三点：

- **机制可核验**：所有能力以 Git 仓库中的实现为准——README、代码结构、测试、评测脚本与运行指标均可被第三方检出并复现。
- **指标真实**：在（小规模）公开或合成数据上真实运行得到数字，不编造、不夸大。
- **可复现**：提供评测脚本与对照实验，任何人在相同数据与环境上可重跑并拿到一致结果。

仓库验收清单（逐条对照）：
- [ ] README：问题定义、架构、快速开始、指标表、对照实验、已知限制
- [ ] 代码结构：config / parsers / chunking / retrieval / generator 分层，单一职责
- [ ] 可运行：`ingest` + `ask` 一键跑通（含轻量后端，零模型下载也能演示）
- [ ] 测试：pytest 至少覆盖解析降级、ACL 拦截、无据拒答
- [ ] 评测：指标脚本可复现，对照实验（纯向量 → +BM25 → +重排 → +改写）
- [ ] 数据：提供下载脚本 + 抽样说明；大 PDF 不纳入 Git（用 .gitignore + 外部下载）
- [ ] 合规：LICENSE、数据来源声明、不含任何第三方保密资产

## 二、质量基线

### MUST（必须满足）
1. 生产级参考实现，非 notebook 片段：模块化、单一职责、配置驱动、有错误处理与降级。
2. 端到端可运行：一条命令入库、一条命令问答。
3. 真实指标：在真实（小规模）数据上跑出真实数字——哪怕只有 8 份年报、50 条标注，也比空泛宣称有力。
4. 诚实：明确标注「哪些是真实能力、哪些是示意 / stub」。编造数字比没有指标更减分。
5. 可复现的评测：RAGAS 或近似指标 + 对照实验脚本。

### NOT（不必做）
- 已上线 SaaS、真实用户量、超高复杂度工程。本项目的目标是展示工程判断力与架构设计能力，不依赖生产流量。

---

## 三、数据真实性与指标真实性必须分开

**原则**：评测不使用真实企业的机密数据。原因有三：

1. **合规红线**：真实客户文档含商业秘密 / 知识产权，一旦公开即构成泄露，且通常受 NDA 约束。
2. **脱敏是额外负担**：若用真实数据，脱敏（PII / 密级遮蔽）本身是一项不可逆的信息损耗工程，对演示无增益。
3. **评测考察的是工程能力，不是某家企业内部文档**：本项目要证明的是在复杂文档解析、分级权限、离线私有化上的架构与实现能力。

**因此：语料以「公开 + 合成」为准，这是正确且主流的做法。** 但必须严格区分两个维度：

| 维度 | 是否要求"真实企业数据" | 真正要求是什么 |
|---|---|---|
| 数据真实性（data authenticity） | 不要求。公开年报 + 合成密级标注 足够且更优 | 来源合法、可开源、无 IP 风险 |
| 指标真实性（metric authenticity） | — | 必须在所提交的（公开 / 合成）数据上真实跑出，且可复现 |

**致命陷阱**：数据既然是合成的，便顺手编一个漂亮指标，这叫「双重伪造」，比没有指标更致命——数字一复现就穿帮。**合法组合 = 合成 / 公开数据 + 真实跑出的指标**；**自毁组合 = 合成数据 + 编造指标**。

**脱敏能力的工程化**：脱敏（自动遮蔽身份证 / 手机号 / 金额等 PII）作为管道内的功能模块实现，可在合成数据上演示其规则与效果。这属于「演示脱敏能力」，是扩展能力而非负担；真实生产环境摄入客户文档时的脱敏作业见第六节。

## 四、数据来源方案

### 路线 1 · 真实公开年报 / 招股书（文档解析）
- 来源：巨潮资讯网 cninfo 公开接口，无需登录 / 付费 / 验证码，返回 PDF 直链；社区已有 cninfo-mcp、开源爬虫可直接用。
- 合规：标注来源、请求限流、不商业再分发；技术验证用途合法。
- 规模：5–10 份即可产出真实指标，不必凑 50 份。

### 路线 2 · 真实公开法规（权限合规的内容）
- 来源：国家法律法规数据库 flk.npc.gov.cn，公开可获取。
- 关键限制：真实法规没有密级标签。权限合规模块的分级权限 / 审计必须在真实内容上做合成标注（构造 public / internal / restricted + 三角色），这是该模块的必要组成，不是偷懒。

### 路线 3 · 合成但拟真的文档（权限合规的 ACL 演示 / 安全兜底）
- 自行撰写「内部制度手册」样张，自带密级标签：零版权风险、完全可控、便于确定性评测。
- 当真实数据获取受阻时的兜底，也是演示 ACL 最干净的方式。

### 计算资源
- 完整链路（docling + BGE-M3 + reranker + LLM）对算力要求较高。
- 开发期用轻量后端（已建 fake 向量 + stub 生成器，零下载可端到端跑）；正式指标在 modest 环境跑一次、如实记录即可。

## 五、各能力模块的数据与达标要点

| 模块 | 数据路线 | 达标要点 |
|---|---|---|
| 文档解析 | 路线 1（5–10 份年报） | 真实解析 / 检索 / 问答指标 + 对照实验表 |
| 权限合规 | 路线 2 内容 + 路线 3 合成密级（必须） | 越权拦截 100% + 三角色演示 + 审计链 |
| Qdrant 生产后端 | 复用上述数据 | 只换部署形态（docker compose + 断网自测） |
| 评测集 | 人工标注 | 50 QA + 30 拒答样本，与数据来源无关 |

## 六、数据脱敏声明与非生产用途说明

### 6.1 项目性质声明
本项目是一个**演示与研究性质的参考实现**，用于展示本地化 RAG 引擎在复杂文档解析、分级权限合规、离线私有化部署三方面的架构与工程能力。

项目所使用的全部语料均为以下两类，**不含任何真实企业的保密或生产数据**：
- **公开数据**：来自巨潮资讯网、国家法律法规数据库等公开渠道；
- **合成数据**：自行撰写的拟真文档与合成密级标注。

所有合成数据均经过**数据脱敏**处理（虚构主体、虚构金额、虚构人名 / 机构名），不存在可关联到真实个人、企业或机构的敏感信息。

### 6.2 不能直接用于工业生产
本项目**不能直接应用于工业生产环境**，原因包括：
- 语料为脱敏 / 合成数据，未经真实业务数据验证；
- 缺乏生产级的安全加固、高可用、灾备与监控；
- 权限模型以配置映射演示，未对接真实身份体系；
- 评测规模为小规模，指标仅证明可行性，不代表生产容量。

### 6.3 工业落地前置工作清单
若要将本项目的能力用于真实工业生产，至少需完成以下工作：

1. **真实数据接入与脱敏管道**
   - 建立真实文档摄入管道（连接器 / 定时同步）；
   - 实现生产级脱敏：PII 自动遮蔽、密级识别与标注、不可逆脱敏留痕；
   - 数据合规审查（来源授权、使用范围、留存期限）。

2. **身份与权限体系对接**
   - 对接企业真实 IAM / SSO（LDAP / OIDC / 钉钉 / 企微等），以真实组织角色驱动 ACL；
   - 将配置映射升级为动态权限策略，支持细粒度与多租户。

3. **安全加固**
   - 传输与存储加密、密钥管理；
   - 向量库与生成服务的访问鉴权、网络隔离；
   - 输入 / 输出内容安全过滤，防止提示注入与数据外泄。

4. **高可用与可运维**
   - 服务冗余、负载均衡、自动故障转移；
   - 数据备份与灾难恢复（含向量库持久化与回滚）；
   - 日志、指标、链路追踪与告警。

5. **评测与质量保障升级**
   - 在真实业务数据上重建评测集，扩大样本规模；
   - 引入回归测试与持续评测流水线；
   - 性能压测（并发、延迟、容量）达到生产目标。

6. **合规与审计**
   - 通过必要的行业合规认证（如等保、ISO 27001 等，视行业而定）；
   - 完善不可篡改审计链，满足金融 / 医疗 / 政企的审计要求；
   - 第三方安全渗透测试。
