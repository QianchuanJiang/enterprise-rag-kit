# 面试演示与界面方案（需求层 · 已锁定）

> 回答两个问题：① 程序员客栈 T3 面试要不要现场演示；② 要不要做可视化 / Web 界面。
> 结论：面试不强制现场演示（核心评价是 Git 仓库代码与架构），但准备演示显著加分；界面**要做，但只做 1 个旗舰场景**，用「录屏 + 本地 Streamlit」组合，且用 stub 后端保证零失败。

---

## 1. 面试要不要现场演示

- 程序员客栈 T3 = 1V1 视频面试，面试官 6 年+大厂 / 50 万+年薪专家。**无"现场演示考试"环节**，考察"项目经验 + 架构思维"。
- **正式证据是 Git 仓库**：README + 代码结构 + 测试 + 评测脚本 + 真实指标。这是面试官真正翻的东西。
- **能"点开看一眼"远胜纯口述**：发一段录屏、或本地起界面让他点，说服力陡增。
- **不把"现场 live 跑全栈"当主力**：网络 / API key / 模型延迟任一出岔子即尬场。

---

## 2. 演示形态（按 ROI 排序，已采纳方案）

| 优先级 | 形态 | 说明 |
|---|---|---|
| 必做 | 仓库 + README | 真正的考核项 |
| ① | **3 分钟录屏** | 零失败、可控、可异步发；覆盖全链路 |
| ② | **1 个 Streamlit 旗舰 UI** | 现场可点开；只做旗舰场景 |
| 不推荐 | 现场全栈 Web 跑 | 风险高，不当主力 |

**已定策略：录屏 + 1 个 Streamlit 旗舰（不做三个 Web）。**

---

## 3. Web 界面范围与技术

- **只做 1 个旗舰 Web UI**：建议放在 **A（解析）** 或统一「知擎」展示页；B/C 用仓库 + README + 录屏覆盖。
- **技术选型**：**Streamlit（前端薄层）+ 已有 FastAPI（后端）**。
  - FastAPI 后端本身**必做**——是给资深工程师看的"工程能力证据"（正确暴露服务，非 notebook）。
  - Streamlit Python 原生，半天可起，无需单独前端栈。
- **红线**：UI 必须调用**真实 pipeline**（哪怕生成用 stub），**不能写成写死答案的假前端**——资深面试官一眼识破。
- **零失败设计**：生成器支持双模式——
  - `stub` 后端：断网、无 API key 也能跑，演示展示检索 / 溯源 / 权限拒绝 / 审计日志，**永不失误**；
  - 真实 LLM：走离线一次跑，指标写入 README。

---

## 4. Web UI 内容清单（面试够用，不追求美观）

- 上传文档 → 看解析出的 chunks（证明解析质量）
- 提问 → 看答案 + 引用（来源 + 页码，证明溯源）
- （B 场景）切换角色登录 → 看不同密级答案 + 审计日志（证明合规）
- 目标：把"真实链路点得通"，而非界面漂亮。

---

## 5. 工作量与优先级

- **面试版**：1 个 Streamlit（~半天）+ 1 段录屏（~1 小时）。**不在 UI 上过度投入**。
- **重金投入 UI 是"接单谈单"阶段**（非技术买家看脸），属后续事项，与面试解耦。
